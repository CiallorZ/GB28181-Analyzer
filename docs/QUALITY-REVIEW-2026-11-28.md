# 前后端全面评估与打磨记录

日期：2026-11-28
基线：`main` @ `62ed7d9`（v1.4.2）
范围：Vue 前端、FastAPI 后端、SQLite 生命周期、上传与存储、AI 配置、Compose 默认部署、依赖与发布检查。

## 1. 总体判断

项目已经具备成熟的 **Windows x64 单机离线协议分析工作台** 形态，不需要重写前端、替换桌面壳或改成分布式架构。最有价值的部分是：

- TShark 取字节、自研 SIP/SDP/RTP 语义解析、规则诊断、证据定位之间的清晰分层；
- 信令状态与媒体状态分离，无法计算的指标保留 `NULL`，TCP 序号缺口不直接等同于网络丢包；
- 从诊断到会话、报文、HEX、视频和报告的完整证据链；
- 本机处理抓包、AI 发送前预览与确认，以及较完整的双主题和响应式界面；
- 已有的后端、前端、Windows、Docker 和仓库卫生 CI 基础。

本轮修复后，代码适合作为下一补丁版本候选继续验收。**这不等于全部发布风险已经清零**：TShark 静默阻塞、清理事务可恢复性、AI 断连后的上游取消仍需优先处理；本机也缺少完整外部工具验收环境。

产品边界应保持为单机离线分析。当前没有账号和授权体系，不应把默认 HTTP API 直接暴露为团队或局域网服务。

## 3. 本轮已完成的修复

### 3.1 前端正确性与交互

- **诊断截断不再产生假“全部正常”**：工作台和精密工作台使用任务汇总中的 critical/warning 数量；只加载部分事件时明确显示“已载入 / 总数”。具体标题只使用与汇总最高等级匹配的已载入事件，否则显示汇总数量并引导查看完整诊断。
- **失败后的重试可以恢复进度**：初始加载和重试共用 `loadTaskAndPoll`，活跃任务不会因第一次请求失败而永久停在旧进度。
- **存储清理有明确确认**：说明上传抓包、报文索引和重建视频的删除范围，以及分析任务跳过规则；按钮更名为“清空所有任务文件”。
- **清理后不再保留旧证据缓存**：按返回的 task ID 清理缓存，彻底清理时清空缓存；当前任务受影响时重新读取。
- **受限浏览器仍可启动**：任务 ID 的 localStorage 读取和写入均有异常保护，恢复值必须是正的安全整数。
- **全局轮询不叠加**：健康检查和活跃任务数在上一次请求结束后才安排下一次；活跃任务刷新合并并发调用并拒绝旧响应。
- **缓存清理与在途请求不再竞争**：旧请求完成时只有仍持有同一 inflight 身份才写缓存或删除登记，避免覆盖新请求。
- **AI 设置可以恢复默认值**：空模型和 base URL 会发送给后端，空 API Key 仍表示保留现有密钥。
- **复制失败不再假成功**：没有 Clipboard API 或权限失败时给出错误，而不是显示已复制。
- **折叠导航名称匹配动作**：收起后无障碍文本变为“展开导航”。

### 3.2 后端与部署

- **续传上传遵守统一大小限制**：`POST /intake/resume` 也执行 `MAX_UPLOAD_MB`，不再使用独立的 16 GiB 清单上限。
- **未完成分片进入磁盘统计**：`.resume-*` 目录递归计入上传占用。注意：孤儿分片回收和严格配额仍是后续项。
- **RTP 提取异常不再伪装成无媒体**：UDP/TCP 的 `CaptureError` 进入任务失败路径，避免形成错误的 `no_media` 诊断。
- **SQLite 增量迁移保留默认值类型**：使用 SQLAlchemy 方言 literal processor，已有行的 Boolean/数值默认值不再变成会回读为真的字符串。
- **线程启动失败有终态**：`Thread.start()` 失败会释放运行预留，并将任务标为失败和“启动失败”。
- **Compose 默认仅本机访问**：仅发布 `127.0.0.1:8080:80`，删除后端 `8788` 宿主映射；对外开放仍必须自行配置认证、TLS 和 Host 白名单。

- ECharts `5.6.0` → `6.1.0`，处理生产依赖 XSS 公告；真实浏览器已验证 6.1.0 能创建并渲染 canvas。

## 5. 第二轮迭代：P1 项已编码完成

首轮评估列出的四个 P1 项均已落地并通过测试：

1. **TShark 静默/无输出 watchdog**（`backend/app/parsers/capture.py`）
   把阻塞的 stdout 读取放进后台 reader 线程，主线程用有界队列 + 单调 deadline 轮询；进程一行不输出或中途卡住也会超时，`finally` 有界 kill/reap。新增 `tests/test_capture_watchdog.py`。

2. **worker 前置异常兜底**（`backend/app/api/tasks.py`）
   `_worker` 增加顶层异常边界，流水线之前的异常用独立会话兜底写 `FAILED`（stage `工作线程异常`），不覆盖 `CANCELLED` 或已写入的更具体失败状态。新增对应测试。

3. **AI 断连取消上游工作**（`backend/app/api/ai.py`、`services/ai.py`）
   SSE 生成器持有 `threading.Event`，客户端断开/超时时 `finally` 置位；worker 用有界队列非阻塞投递；`_post` 在发送前和流式读取每个分块检查取消事件并及时关闭上游响应。新参数向后兼容。新增 `tests/test_ai_cancellation.py`。

4. **存储清理可恢复性与保留策略一致性**（`backend/app/services/retention.py`、`main.py`）
   清理改为三阶段：文件移入 `DATA_DIR/quarantine/<task_id>` 并记录 manifest → 数据库提交 → 成功后删隔离区；提交失败按 manifest 恢复。`reconcile_quarantine()` 在启动时经 `auto_purge` 协调。实现 `KEEP_UPLOADS=False`（只清原始抓包、保留视频与结果）和 `cleanup_orphan_resumes()`（默认 24 小时回收 `.resume-*`）。新增 `tests/test_retention_reliability.py`。

第二轮验证：后端 **355 passed，8 skipped**；前端 **73 passed**；Ruff、ESLint、构建、体积预算（99.4 KB / 110 KB）、npm/pip 依赖审计均通过。相对首轮基线新增 12 项后端测试（含三个新测试文件）。

## 6. 建议的迭代方式

保持 FastAPI + SQLite + Vue + Native Shell 的边界，按以下顺序推进：

1. 子进程 watchdog、AI 取消、清理事务恢复；
2. Windows 真实工具链和大抓包回归；
3. SIP 键盘/大数据量交互和组件浏览器测试；
4. 再考虑 RTCP 时间轴、首帧口径、交互拓扑等专业功能。

不建议把下一轮投入用于更换 UI 框架、重写 Rust 解析器或直接扩展团队数据库；这些都不是当前最主要的风险来源。
