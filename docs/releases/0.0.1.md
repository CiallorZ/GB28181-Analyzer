# GB28181 Analyzer 0.0.1

首个公开发布版本（2026-11-19）。定位是**内网可用**的单用户抓包分析工具：
上传 PCAP，还原一次 GB/T 28181 点播从 SIP 协商到 RTP 收流的全过程，
给出可追溯到报文的质量指标与故障结论，并能导出 Markdown / JSON 报告。

版本号从内部基线 `1.0.0-P0` 重新起算。0.0.1 表示链路闭环、可以试用，
不代表生产就绪 —— 未验证项在下方逐条列出。

## 这一版有什么

**协议与统计**

- SIP / SDP 解析（含 `y=`、`f=`、`setup`、`xstreamtype` 国标扩展），Dialog 与会话重建
- UDP 与 TCP(RFC4571) 两种承载；序号回绕、丢包、乱序、重复、RFC 3550 抖动、码率
- MPEG-PS → PES → ES 解封装，H.264/H.265 识别，按访问单元（AU）统计 I/P/B 帧
- 参数集对齐后用 ffmpeg 还原 MP4，前端直接播放
- 21 条诊断规则中 12 条已接入，每条带证据等级、证据、可能原因与排查建议；
  其余在设置页明确标注「规划中」，不假装已覆盖

**报告导出（本版新增）**

- `GET /api/v1/tasks/{id}/report?format=md|json`，只读已入库结果，不重跑分析
- Markdown 五节：结论摘要 / 信令会话 / 媒体流 / 诊断明细 / 分析范围
- JSON 字段与页面接口一致，便于脚本二次处理
- 工作台提供导出入口：桌面下拉，移动端平铺 `.md` / `.json`

**工程与可信度**

- 六轮迭代（R1–R6）：SDP 正文、诊断排序、RFC4571 大包、PS 帧数口径、
  TCP 方向拆分等会**静默算错**的问题已修
- 后端 158 个测试、覆盖率 72.86%，门槛 70%；ruff、ESLint、Vitest、CI 五个 job
- 大抓包不再保留全量报文列表；媒体重建按 CPU 核数并发
- 版本号单一来源；`DEBUG` 默认关闭；支持 `.env`（环境变量优先）

## 安装

```bash
# 依赖：Python 3.10+、Node.js 18+、tshark 4.x；视频还原另需 ffmpeg 6.x
cd backend
python -m venv .venv
.venv\Scripts\activate            # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8788

# 另开终端
cd frontend
npm install
npm run dev                       # http://localhost:5173
```

Docker：`docker compose up --build`，前端 8080、后端 8788。
对外部署前必须设置 `ALLOWED_HOSTS`，并在反向代理层加认证（本服务没有账号体系）。

## 已知限制

- **未做 RTCP**：丢包率与往返时延只能由 RTP 侧推断
- **报告只有 Markdown / JSON**：HTML 单文件与 CSV 未做
- **Docker 镜像未在真实 Docker 环境运行验证**：CI 只构建镜像、校验 compose
- **PostgreSQL 未在真实环境验证**：默认 SQLite，schema 兼容 PG
- **无数据库迁移**：升级已有库可能缺列（后续接 Alembic）
- **H.265 不区分 B 帧**；抓包缺 SPS/PPS 时无法还原画面
- **TCP 承载的到达时间是插值**，码率/抖动精度低于 UDP
- 尚无分片上传（上限 2GB）、无设备拓扑图、无实时采集

## 回滚

`git revert <release-commit>`；或使用上一版本源码包重新部署。
数据库无 schema 变更，回滚不需要迁移。
