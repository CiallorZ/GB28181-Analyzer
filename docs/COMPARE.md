# 双抓包对比

设备侧和平台侧各自完成一次分析后，打开导航中的「双包对比」。分别选择任务 A、B，可填写“设备侧”“平台侧”等标签。A 是相对码率差的基准。创建快照后，可在五个分区核对字段、切换「只看差异（含未知）」、展开未对齐项或导出报告。

## 对齐方法与置信度

| 对象 | 精确对齐 | 低置信度推断 | 出现冲突时 |
| --- | --- | --- | --- |
| 会话 | 两侧至少共享一个 Call-ID，且由共享 Call-ID 连接的候选组为一对一 | 设备编号、通道编号、会话类型均有值，且组合在两侧各出现一次 | 同一组包含多个候选时标记歧义，保留各侧编号；无候选则列为未对齐 |
| 媒体流 | 在一对已对齐会话内，非空 SSRC 一对一相等，SSRC 为 0 仍是有效值 | 传输方式和载荷类型均有值，且组合在该会话的两侧各出现一次 | 冲突、缺少候选、未归属会话的流均单列 |
| 诊断 | 以规则编号比较事件数与已记录的最高严重级别 | 无 | 保留任务级事件；关联到未对齐会话或流的事件单列 |

精确键优先，已占用的记录不会再次配对。会话层只使用表中列出的键。推断属于低置信度，媒体流继承父会话的低置信度。页面与报告保留对齐所用的键值。诊断事件的会话和流编号始终在本侧任务内解析，双方事件不做逐条配对。

## 字段与容差

| 层面 | 核对内容 |
| --- | --- |
| 信令与会话 | 信令状态、媒体状态、结束方式、INVITE 耗时、首媒体与首关键帧耗时、媒体与会话时长、入库流数及严重和警告计数 |
| SDP 协商 | 协商地址、端口、传输方式、Subject 和 SDP SSRC、协商耗时 |
| 媒体传输 | 流存在性、SSRC、载荷类型、传输、包数、平均与峰值码率、序号缺口、乱序、重复、抖动、最大静默、中断数 |
| 编码与重建 | 源编码、宽高、帧率、关键帧数、是否观察到音频、已记录的重建结果 |
| 诊断规则 | 每侧事件数、最高严重级别 |

| 数值类别 | 判为超出对比容差的条件 |
| --- | --- |
| 耗时、时长、最大静默 | 绝对差大于 0.05 秒 |
| 平均与峰值码率 | 绝对差大于 A 侧绝对码率的 10% |
| 平均与最大抖动 | 绝对差大于 5 毫秒 |
| 序号缺口、乱序、重复包数 | 绝对差大于 10 包 |

门限采用严格大于。A 为 100、B 为 110 时判为一致；B 为 110.1 时判为超出对比容差。A 为 0 时，双方均为 0 判为一致，B 非零即超出容差。其他字段精确比较。默认值在 `backend/app/services/comparison.py` 的 `TOLERANCES` 中配置，创建时复制进快照。

字段记录为 `[A值, B值, 判定]`。`same` 含容差内一致，`different` 为直接不等或超容差，`unknown` 表示缺乏可比较值。原始空值保留为 JSON null，界面呈现“未知”；数量 0 和布尔值 false 各自保留。`only_a`、`only_b` 表示仅该侧观察到，`ambiguous` 表示候选存在歧义。重建类别由入库的成功产物路径或失败记录确定，二者皆缺时为未知。

差异统计只使用对齐对象；单侧规则的缺失数量保留为 null。会话字段中的媒体流数、警告数等是各任务已经记录的观测值。未对齐记录及其数量单独展示，不参与差异统计。每层明细共享上限，优先保留存在差异的配对，再保留未知与一致项。未对齐项可预留四分之一容量，歧义优先，两类共用余量；截断时列出每层差异与未对齐记录的保留数和总数，会话最多 200、流最多 500、诊断最多 300。完整计数分别保存在 `totals` 和 `unmatched_totals`；超限时 `truncated` 为 true。

## 快照与导出

快照保存两侧任务编号、完成时间、文件名及 checksum、会话数、媒体流数。读取时核验任务状态与指纹，任一侧发生变化即标记 `stale`。旧快照继续显示创建时的数据，可导出，并关闭双方证据跳转。报文索引被清理或会话目标消失时，该目标的跳转也会关闭。

Markdown 包含范围、生成时间、指纹、过期状态、对齐依据、摘要、五层差异、未对齐项、未知项与局限说明。JSON 和详情接口返回相同的数据结构；`stale` 和 `links` 反映读取时的状态，`fingerprint`、`result`、`summary` 保留创建时的值。快照只读取入库观测数据。创建和导出均无需抓包文件、网络 AI 服务、TShark 或 FFmpeg。

删除任一源任务会级联删除比较。启用 `KEEP_DAYS` 时，保留策略按快照自身的创建时间清理过期记录。如需长期留档，请先导出报告。

## API

所有路径使用前缀 `/api/v1`。

| 方法与路径 | 用法 |
| --- | --- |
| POST /comparisons | 必填整数 task_a_id、task_b_id；可选 label_a、label_b，最多 100 字符，过滤控制字符。201 返回详情 |
| GET /comparisons?limit=20&offset=0 | 返回 total、items，最新快照优先。limit 范围 1–100 |
| GET /comparisons/{id} | 读取快照及 stale、links |
| GET /comparisons/{id}/report?format=md | 下载 Markdown，format=json 下载 JSON；文件名使用快照编号 |
| DELETE /comparisons/{id} | 删除快照，成功返回 204 |

自比请求返回 400，任务或快照缺失返回 404，任务未完成返回 409。算法自比在单元测试中验证；产品入口要求两个不同任务。

## 性能复验

在 backend 目录执行 `python -m pytest tests/test_comparisons.py -k typical_scale -s -q`。测试在临时文件型 SQLite 库中为每侧准备 500 个会话、每会话 4 条流。计时从 TestClient 发起 POST 到完整响应返回，包含查询、对齐、统计、序列化和提交，排除造数。本机 Windows 实测 **0.154 秒**，响应 **560,839 字节**，保存 200 对会话、500 对流明细，完整计数 500 对会话、2,000 对流。该用例为构造数据，无诊断事件；不同硬件、磁盘负载和诊断量会影响耗时。

## 局限

- 对比只描述两侧观察到的结果差异，不证明差异发生的位置或原因。
- 抓包点、时间窗、过滤条件不同都会造成差异。
- 未对齐项不能视为「不存在」。
- 过期检测依据上述指纹。同一指纹下直接改写库内字段无法据此识别；原快照仍可复现。
